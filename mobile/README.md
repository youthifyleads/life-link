# Life Link Mobile Application

Flutter mobile application for the Life Link blood coordination network, serving citizens acting as **Donors** and **Caregivers** (`NormalUser` role).

---

## 📱 Role & Target Users

The mobile app is designed for citizens:
- **As a Donor**: Find nearby emergency blood requests matching your blood type, receive urgent notifications from blood banks, accept requests with one tap, and manage your donation records.
- **As a Caregiver**: Scan hospital-issued blood bag QR codes during patient transport or treatment to verify bag authenticity, origin blood bank, and blood type.

Both personas share the same `NormalUser` account; caregiver access is automatically available to any registered user.

---

## ✨ Core Features & User Flows

### 1. Donor Experience
- **Profile & Home Location**:
  - Save blood type (`O-`, `O+`, `A-`, `A+`, `B-`, `B+`, `AB-`, `AB+`), birth date, governorate, and home GPS coordinates (`latitude`, `longitude`).
  - Home coordinates enable accurate distance calculation to hospitals and blood banks.
- **Nearby Blood Requests Feed (`GET /api/v1/donors/me/nearby-requests`)**:
  - Displays open hospital blood requests compatible with your blood type, ordered from nearest to farthest (Haversine formula).
  - Shows hospital name, governorate, distance in km, blood type, component, and urgency status.
  - **Auto-Fulfillment / Quota Management**: Requests automatically disappear from the feed as soon as enough donors have accepted (`accepted_count == quantity_units`).
- **Urgent Notifications**:
  - Instant alerts when a blood bank or hospital requests nearest donors.
  - Tapping a notification opens the request details with an action to accept or decline.
- **Request Response (`POST /api/v1/donors/me/responses`)**:
  - Accept or decline with optional notes.
  - If another donor already fulfilled the last needed bag, the system gracefully informs you:
    `"تم اكتمال العدد المطلوب من المتبرعين لهذا الطلب بالفعل. شكراً لمبادرتك النبيلة!"` (`422 REQUEST_ALREADY_FULFILLED`).
- **Donation History & Consents**:
  - Track completed donations (`GET /api/v1/donors/me/donations`) and eligibility interval (6 months / 180 days).

### 2. Caregiver Blood Bag QR Scanner
- **Scan Blood Bag (`POST /api/v1/caregiver/scan-bag` or `GET /api/v1/caregiver/bag/{qr_code}`)**:
  - Open camera scanner to read the QR code on the blood bag (generated by hospital staff).
  - Displays strictly the safe, essential information needed for the caregiver:
    - **Blood Bank Name** (`bank_name`)
    - **Location** (`bank_location`)
    - **Bag Status** (`status`)
    - **Blood Type** (`blood_type`)
    - **Blood Bag ID** (`blood_bag_id`)

### 3. Authentication
- **Phone OTP Sign-in**:
  - Request OTP: `POST /api/v1/auth/otp/request`
  - Verify OTP: `POST /api/v1/auth/otp/verify` (Fixed development OTP: `123456`).
- **Email & Password Sign-in**:
  - `POST /api/v1/auth/login`
- **Default QA Donor Account**:

  - Role: `NormalUser`

## 🛠️ API Reference Summary

| Flow | Endpoint | Method | Description |
| :--- | :--- | :--- | :--- |
| **Auth** | `/api/v1/auth/otp/request` | `POST` | Request 6-digit OTP to phone number |
| **Auth** | `/api/v1/auth/otp/verify` | `POST` | Verify OTP (use `123456` in dev) & receive JWT |
| **Auth** | `/api/v1/auth/login` | `POST` | Email & password login |
| **Donor** | `/api/v1/donors/me` | `GET` / `POST` / `PATCH` | Manage donor profile & home GPS location |
| **Donor** | `/api/v1/donors/me/nearby-requests` | `GET` | Feed of open compatible requests sorted by distance |
| **Donor** | `/api/v1/donors/me/responses` | `POST` | Accept/decline request (`{"blood_request_id": "...", "status": "accepted"}`) |
| **Donor** | `/api/v1/donors/me/donations` | `GET` / `POST` | List completed donations |
| **Caregiver** | `/api/v1/caregiver/scan-bag` | `POST` | Scan bag QR and retrieve bank name, location, status, type |
| **Caregiver** | `/api/v1/caregiver/bag/{qr_code}` | `GET` | GET alias for bag QR scan |
| **Caregiver** | `/api/v1/caregiver/assignments` | `GET` | List caregiver assignments |
| **Notifications** | `/api/v1/notifications` | `GET` | In-app notification center |
| **Notifications** | `/api/v1/notifications/{id}/read` | `POST` | Mark notification as read |

Detailed contracts and payloads are documented in [`backend/docs/MOBILE_API_CONTRACT.md`](../backend/docs/MOBILE_API_CONTRACT.md) and [`backend/docs/API_SPEC.md`](../backend/docs/API_SPEC.md).

## 🚀 Getting Started Locally

### Prerequisites
- Flutter SDK (≥ 3.19.0)
- Dart SDK (≥ 3.3.0)
- Android Studio / VS Code with Flutter extensions
- Android Emulator or physical device

### Installation & Run

1. **Navigate to the mobile directory**:
   ```bash
   cd mobile
   ```

2. **Install dependencies**:
   ```bash
   flutter pub get
   ```

3. **Configure API Base URL**:
   Set your backend host:
   - **Android Emulator**: `http://10.0.2.2:8000/api/v1`
   - **iOS Simulator**: `http://localhost:8000/api/v1`
   - **Physical Device**: `http://<YOUR_LOCAL_IP>:8000/api/v1`
   - **Azure Backend**: `https://lifelink-backend-dev-g7cwf7gsf3cxdaba.centralus-01.azurewebsites.net/api/v1`

4. **Launch the application**:
   ```bash
   flutter run
   ```
